| 4. Reconstruct intent | `pm-lead` → `spec-writer` | `_agency/spec-as-is.md`, with unknowns listed as questions |
| 5. Integrity, then report | `qa-lead` → `test-runner` (`git status --porcelain`, `git rev-parse HEAD`); CEO | `_agency/baseline/integrity.md`; `_agency/adoption-report.md`, with any write outside `_agency/` reported as a breach. Then the CEO stops for the Chairman's approval (step 6) |

Every dispatch starts with a word-for-word **adoption brief**: do only this one task, write only this one file, change nothing else, and pass the brief on. Without it, the five other chiefs would run their build-from-nothing processes: test design, CI and `deploy/` files, and `threat-model.md` at the root. `dlp-scanner` and `sbom-slsa` were dropped after their bodies were read. One guards outbound calls and the other attests releases; neither scans a repository. "No code changes" rests on the brief plus the step 5 check, **not on the guard**. If a specialist's write is refused (as in D3a), it returns the text and its chief writes it unchanged.

On re-entry, the skill compares the recorded adoption commit with the current one and re-maps first if they differ. This is the simplest form of the plan's drift rule.

## Also in this PR: an advisory pipeline report (a first 5-lite piece)

`scripts/pipeline_report.py <project-dir>` reads the guard's receipts and flags each chief that wrote a file but dispatched no agent of its own council. It is read-only and log-only: it blocks nothing, so it needs no E4 decision.
- The ceo and the board director are exempt.
- Dispatches outside a chief's own council don't count. Cross-council dispatch is still an open decision (2a pack, D3), and the flag line lists those dispatches.

## Release check (advisory), 2026-11-24

`scripts/release_check.py <launch-dir> [--project <folder>] [--since <time>]` checks a **ship**, not an adoption. For each council `CONSTITUTION.md` §3.3 makes blocking (CISO, CEVO, CRT, CAO), it reports whether the council was convened and whether it recorded a verdict.

- **What counts as a verdict:** a file written by an agent of that council. The shared logs `chat.jsonl`, `inbox.json` and `_sessions/` don't count.
- **`status.json` never stands in.** It is read from the documented shape, `gates.byCouncil` and `gates.waivers`. The CEO writes `status.json`, so a gate entry there never replaces a council's own record.
- **A red** clears only with a waiver in `gates.waivers` marked `"waivedBy": "user"` for that council.

Replay results:

| Run | Result |
| --- | --- |
| G1, G2 | CEVO, CRT and CAO flagged: never convened |
| R3 (positive control) | No flags: all four councils convened and recorded |

Limits:
- It is advisory and blocks nothing. Making it a gate is E4.
- Receipts accumulate across runs in a launch folder. `--project` narrows writes by path, but dispatches carry no path, so use `--since` for those.
- No recorded run used the documented `status.json` gate shape: G1, G2, R3 and D3a each wrote their own layout. So the gate half was tested only with fixtures.
